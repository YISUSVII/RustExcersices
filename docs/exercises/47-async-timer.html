Exercise 47 · Level 15 — Async Rust

Async Timer

Understand how futures, wakers, and executors fit together by writing a minimal block_on executor and a TimerFuture using only the standard library.

Advanced`Future` trait`Poll``Pin``Context``Waker``std::task::Wake`thread parking`async`/`.await`

Real projects use a runtime. In production you'd write #[tokio::main] async fn main() and tokio::time::sleep(..).await. Tokio is an external crate, so this exercise builds the same pieces by hand with std only — that way you see what a runtime does for you, and the file compiles with plain rustc.

Instructions

  1. Implement a waker: struct ThreadWaker(Thread); with impl Wake for ThreadWaker whose wake calls self.0.unpark().
  2. Implement fn block_on<F: Future>(fut: F) -> F::Output: - pin the future (std::pin::pin!), - build Waker::from(Arc::new(ThreadWaker(thread::current()))) and a Context, - loop: poll; on Poll::Ready(v) return v; on Poll::Pending call thread::park().
  3. Implement struct TimerFuture { state: Arc<Mutex<TimerState>> } where TimerState { completed: bool, waker: Option<Waker> }: - fn TimerFuture::new(duration: Duration) -> TimerFuture spawns a thread that sleeps, sets completed = true, and calls wake() on the stored waker. - impl Future for TimerFuture (Output = ()): return Ready if completed, otherwise store cx.waker().clone() and return Pending.
  4. Add fn sleep(duration: Duration) -> TimerFuture and async fn countdown(from: u32, tick: Duration) -> u32 that prints from..=1 while awaiting a timer each tick, returning the number of ticks.

Expected behavior

  • block_on(async { 6 * 7 }) → 42.
  • block_on(sleep(Duration::from_millis(100))) returns after ~100 ms.
  • block_on(countdown(3, 50ms)) prints 3... 2... 1... and takes ~150 ms (awaits run sequentially).
  • A freshly created timer returns Poll::Pending on its first poll.

Optional hints

  • A future does nothing until polled. Pending is a promise: "I stored your waker and will call it when I can make progress."
  • The timer thread must lock the state, set completed, and take the waker in the same critical section that poll uses, or a wake-up could be lost.
  • thread::park may return spuriously — that's why block_on polls in a loop.

Bonus challenge

Compare with the Tokio version (requires tokio = { version = "1", features = ["full"] } in Cargo.toml):

        println!("{n}...");

use std::future::Future;
use std::pin::{pin, Pin};
use std::sync::{Arc, Mutex};
use std::task::{Context, Poll, Wake, Waker};
use std::thread::{self, Thread};
use std::time::{Duration, Instant};

/// Wakes the executor by unparking the thread that is blocked in `block_on`.
struct ThreadWaker(Thread);

impl Wake for ThreadWaker {
    fn wake(self: Arc<Self>) {
        self.0.unpark();
    }

    fn wake_by_ref(self: &Arc<Self>) {
        self.0.unpark();
    }
}

/// Minimal single-future executor: poll, and park the thread until woken.
fn block_on<F: Future>(fut: F) -> F::Output {
    let mut fut = pin!(fut);
    let waker = Waker::from(Arc::new(ThreadWaker(thread::current())));
    let mut cx = Context::from_waker(&waker);
    loop {
        match fut.as_mut().poll(&mut cx) {
            Poll::Ready(output) => return output,
            // `park` may wake spuriously; that's fine, we just poll again.
            Poll::Pending => thread::park(),
        }
    }
}

#[derive(Default)]
struct TimerState {
    completed: bool,
    waker: Option<Waker>,
}

/// A future that completes after `duration`, driven by a background thread.
struct TimerFuture {
    state: Arc<Mutex<TimerState>>,
}

impl TimerFuture {
    fn new(duration: Duration) -> TimerFuture {
        let state = Arc::new(Mutex::new(TimerState::default()));
        let thread_state = Arc::clone(&state);
        thread::spawn(move || {
            thread::sleep(duration);
            let mut s = thread_state.lock().unwrap();
            s.completed = true;
            if let Some(waker) = s.waker.take() {
                waker.wake();
            }
        });
        TimerFuture { state }
    }
}

impl Future for TimerFuture {
    type Output = ();

    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<()> {
        let mut s = self.state.lock().unwrap();
        if s.completed {
            Poll::Ready(())
        } else {
            // Always store the latest waker: the future may have moved to another task.
            match &s.waker {
                Some(w) if w.will_wake(cx.waker()) => {}
                _ => s.waker = Some(cx.waker().clone()),
            }
            Poll::Pending
        }
    }
}

fn sleep(duration: Duration) -> TimerFuture {
    TimerFuture::new(duration)
}

async fn countdown(from: u32, tick: Duration) -> u32 {
    let mut ticks = 0;
    for n in (1..=from).rev() {
        println!("  {n}...");
        sleep(tick).await;
        ticks += 1;
    }
    ticks
}

}
